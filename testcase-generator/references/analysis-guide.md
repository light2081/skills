# 测试用例分析指南

## 适用范围

用于根据需求文档或功能说明生成功能测试用例，重点保证模块划分清晰、场景覆盖完整、输出字段统一。

## 分析顺序

1. 识别模块
2. 识别功能点
3. 识别字段约束
4. 识别角色与权限
5. 识别状态与依赖
6. 生成场景并补漏

## 模块拆分规则

- 一级标题通常对应一级模块
- 同一页面中若存在相互独立的业务目标，应拆分为多个功能点
- 登录方式不同、角色不同、状态不同，优先拆开处理
- 展示规则、字段回填、按钮显隐、跳转路径、文件下载、打印、新标签打开，也应单独识别为测试点

示例：

- “用户登录”应继续拆为“账号密码登录”“短信验证码登录”“第三方登录”
- “订单管理”应继续拆为“创建订单”“取消订单”“支付订单”“导出订单”

## 详细化生成原则

当目标是“生成更详细的测试用例”时，默认采用细粒度展开，不主动合并场景。

### 拆细优先级

优先按以下维度继续拆分：

1. 不同角色或认证等级
2. 不同状态或节点
3. 不同入口或按钮
4. 不同字段校验类型
5. 不同结果页面或结果文案
6. 不同显隐和交互行为

### 不要合并的典型场景

以下内容应拆成多条，而不是写成一条综合用例：

- 空值校验、格式校验、长度校验
- 校验通过、校验失败
- 默认显示、点击跳转、返回原页面
- 按钮显示、按钮点击、按钮点击后的结果
- 查看证明、下载证明、打印证明
- 首次登录回填、再次登录更新、用户修改后保留

### 等价类

每个字段至少考虑：

- 合法输入
- 空值
- 格式错误
- 长度不足
- 长度超限
- 业务规则无效

文本字段额外考虑：

- SQL 注入
- XSS
- 首尾空格
- 特殊字符

字段级最低展开建议：

- 必填字段：至少 3 条，合法值/空值/业务或格式非法值
- 长度字段：至少 4 条，下边界前/下边界/上边界/上边界后
- 枚举字段：每个合法枚举值至少 1 条，无效值至少 1 条
- 只读字段：至少 1 条验证不可编辑
- 自动回填字段：至少 1 条验证回填正确，1 条验证无数据时展示规则

### 边界值

对存在长度、数值、日期、数量范围的字段，至少覆盖：

- 最小值前一位
- 最小值
- 最大值
- 最大值后一位

### 判定表

出现以下信号时使用：

- “当……且……时”
- “如果……或……则”
- 多个条件共同决定一个结果
- 会员、优惠券、满减、角色、状态等组合规则

### 错误猜测

优先补充以下高风险场景：

- 双击提交
- 并发提交
- 过期 token 重放
- 越权访问
- 文件格式绕过
- 已终态对象重复操作
- 新标签打开失败或打开内容错误
- 下载文件名错误、下载内容错误
- 打印入口显隐错误
- 脱敏字段未脱敏或脱敏过度
- 配置关闭后入口仍显示

## 覆盖清单

每个功能点完成后检查：

- 是否有正常流程
- 是否有异常流程
- 是否有边界值
- 是否有权限校验
- 是否有数据落库校验
- 是否有状态流转校验
- 是否有并发或重复提交校验
- 是否有显隐校验
- 是否有跳转或返回校验
- 是否有默认值/回填/只读校验
- 是否有提示文案校验
- 是否有下载/打印/新标签校验

## 优先级建议

- `High`：核心链路、资金、权限、主操作流程
- `Medium`：重要但非阻断路径，常规异常与一般校验
- `Low`：边缘功能、低频场景、次要提示文案

## 大文档处理策略

当需求很大时，不要把整份文档一次性展开后直接生成全部用例。必须采用降上下文策略。

### 分阶段处理

1. 首轮只提取目录、章节、模块名、角色、状态、关键业务动作
2. 形成模块索引表，不在这一轮展开详细测试用例
3. 第二轮开始按模块逐个读取对应章节
4. 每完成一个模块，立即输出该模块 JSON
5. 全部模块完成后，再统一合并并导出 Excel

对于 `.txt` 或 `.md` 大文档，优先运行：

```bash
python "<skill_dir>/scripts/split_requirements.py" "<input_file>" "<output_dir>"
```

脚本输出：

- `module_index.json`：模块索引、行号范围、预览摘要
- `modules/*.txt`：每个模块的独立文本

后续生成测试用例时，只读取 `module_index.json` 和当前处理模块的文本文件。

### 上下文控制规则

- 当前上下文只保留“全局规则 + 当前模块细节”
- 已完成模块只保留摘要与输出文件路径，不保留完整用例正文
- 如果单个模块仍然很大，继续按子模块、页面、角色或状态拆分
- 优先使用文件落盘而不是在对话里长期堆积大段中间结果

### 推荐拆分粒度

- 一级模块过大时，按二级标题拆
- 二级标题仍过大时，按功能点拆
- 状态流转复杂时，单独拆出“状态流转用例”
- 权限矩阵复杂时，单独拆出“权限/角色用例”

### 目标

通过“模块索引 -> 分批生成 -> 模块落盘 -> 最终合并”的方式，避免因为上下文过大导致模型只生成少量用例或遗漏边界场景。
