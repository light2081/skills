# 测试用例字段规范

## 标准列头

输出 Excel 或 JSON 时使用以下列头：

`功能模块, 用例编号, 功能点, 用例标题, 优先级, 前置条件, 测试步骤, 预期结果, 设计人, 执行结果, 执行人, 备注`

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 功能模块 | 是 | 归属模块名称 |
| 用例编号 | 是 | 模块内唯一编号，建议 `模块缩写_001` |
| 功能点 | 是 | 单一业务功能点 |
| 用例标题 | 是 | 简洁说明测试目标 |
| 优先级 | 是 | `High`、`Medium`、`Low` |
| 前置条件 | 是 | 执行前需要满足的条件，可多行 |
| 测试步骤 | 是 | 具体步骤，可多行 |
| 预期结果 | 是 | 可验证的结果，可多行 |
| 设计人 | 否 | 默认空字符串 |
| 执行结果 | 否 | 默认空字符串 |
| 执行人 | 否 | 默认空字符串 |
| 备注 | 否 | 默认空字符串 |

## 编号规则

- 优先使用英文模块缩写，例如 `LOGIN_001`
- 未知中文模块可用拼音首字母，例如 `DDGL_001`
- 同一模块内连续编号，不重复

## 标题规则

推荐格式：

- `验证登录成功`
- `验证手机号为空时提交失败`
- `验证订单已取消时不可重复支付`

避免使用：

- `测试1`
- `功能测试`
- `场景验证`

## 编写要求

- `测试步骤` 写成可执行动作，不要只写测试意图
- `预期结果` 写成可观察结果，不要写“系统正常”
- 单条用例只验证一个主要业务目标
- 需要换行时在单元格中保留换行文本
